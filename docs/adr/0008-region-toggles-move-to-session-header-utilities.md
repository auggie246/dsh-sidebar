# Session toggles use the header position; the right-edge Rail stays hero-only

The Rail pinned both region toggles to the right edge of the GUI at all times (`position: fixed; top: 50%; right: 0` in the `shell.overlay` layer). In a working session the DSH shell renders its Turn Navigator — the vertical rail of turn marks that lets a long conversation jump between turns — in the rightmost ~12–40px of the center conversation column, vertically centered (`dsh-client-ui-chat`, a 28px-wide frame at `right: calc(12px - (var(--dsh-composer-side-clearance) + 16px))`, z-index 7). The two bars sit at exactly the same place at exactly the same height: the Rail's z-index 60 and `pointer-events: auto` covered the turn-mark lane and stole its clicks, and the marks rendered into the Rail's footprint. Moving the Rail vertically does not dodge a vertically centered marker band, and insetting it horizontally leaves a bar floating over conversation text.

We decided the right-edge Rail stays on the hero page, where no session or Turn Navigator exists. A blank session uses the same horizontal Header Toggles appearance at the real header's top-right button position (`top: 14px; right: 28px`) through `shell.overlay`, because DSH hides the header in that state. Once the session starts, the same two-button pair (Sidebar toggle, Panel toggle) renders in the shell's `conversation.session.header.utilities` slot. The controls therefore stay in nearly the same place across the blank-to-started transition. The Navigator remains clear because the only overlay copy exists before the session starts. Every seat builds its pair from one shared `createRegionToggleButtons` factory, so handlers, glyphs, titles and disabled logic cannot drift. The `shell.overlay` occupant still mounts the regions themselves (the bottom Panel and the blank-session overlay Sidebar) in every state. The Rail component keeps owning the layout effect that docks and closes the Details Column.

Consequences. A blank new session has both region entry points without restoring the old centered Rail or creating a large position change. After the first message starts, the toggle chrome moves into the real session header, VS Code title-bar style. CONTEXT.md defines the Rail as hero-only and Header Toggles as both blank-session and started-session controls. Rejected alternatives: restoring the centered Rail on blank sessions, which makes the controls jump when the session starts; re-anchoring the Rail to a corner that the Navigator's centered band could still reach on short viewports; and insetting the Rail by the navigator lane width, which places a 22px bar over chat content and still guesses at shell-internal geometry (`--dsh-composer-side-clearance`) this repo does not own.
