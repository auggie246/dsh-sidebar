# Terminal output rides a long-poll pull RPC, not a push channel

Terminal Panel Tabs are backed by real PTYs spawned through `ctx.subprocess.spawnTerminal` (node-pty already ships with DSH). Getting stdout to the browser is the constrained half: the plugin's Typert remote channel is request/response only, and the host→client `host/remote-event` push path has a hardcoded closed allowlist of 11 events with no runtime extension point. We decided output is served by a pull RPC the host holds open for ~1s until output arrives, reading from a bounded ring buffer (~100KB) kept per shell; the buffer also backs reload re-attach. The rejected alternative — appending each output chunk as a merge-extended session event to ride the unfiltered `session/event` WebSocket forwarding — gives true push, but every chunk would become a permanent entry in the session's durable append-only log, which is the wrong durability for megabytes of terminal scrollback. PTY sessions live in the host process and are lost on `dsh web` restart; only page reloads re-attach.

Mechanism note (ticket #9, terminal lifecycle): session ids embed a per-boot nonce (`pty-<boot>-<counter>`), so a stored tab id can never match a later boot's shell. A page reload re-attaches by pulling the ring buffer from seq 0, and a pull reporting an unknown session is unambiguous evidence of a host restart — the client renders a dead-session placeholder instead of a broken terminal, and no tab can ever attach across boots.
